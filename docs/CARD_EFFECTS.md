# Card data and effects (for the TF3 Cards mod and card editors)

How the game stores one card's behaviour, and what the tools in this repository can write. Everything here was checked against Tag Force 1 (EU) running in the recompilation.

## The card map

`python -I tools/game/mapa_cartas.py [out.json]` builds one JSON file with every card of Tag Force 1 and Tag Force 3:

* cards are matched across the games by the 8-digit passcode (`CARD_Pass`), by name when the passcode is 0;
* per card: ids in both games, name, passcode, category, kind (monster / spell / trap), ATK, DEF, level, both texts and the effect record of each game;
* `handlers_tf3`: for every TF3 handler, the TF1 handler learnt from the cards both games share (`mapped` / `conflict` / `unmapped`);
* `donor`: the shared card with an identical record whose text reads most like the card's (a hint, not a guarantee);
* `ids_novos()` lists the cards that exist only in TF3.

The file holds game text, so it is written to `gen/` and kept out of git.

## How a card works in a duel

1. **Data**: `CARD_Prop` (stats, category, type, attribute), `CARD_Pass`, `CARD_Genre`, names and descriptions, all in `cardinfo_<lang>.ehp`.
2. **Effect record**: six words `{card id, 5 handler pointers}` in four tables of `libduel_eng` (found by hook `09eb4574`). Only about 1500 of the 2480 cards have one. A record names a *generic* handler: a step machine that returns the next step number and calls engine primitives. Two cards with the same handler can still behave differently.
3. **Per-card code**: the card-specific part lives either in a function table keyed by id (the candidate scan, `09f76818`, 364 entries) or in chains of `if (id == N)` inside shared functions (passive monster effects, stat changes, equip rules, costs). The chains cannot be extended with data.

## Effects in data (TF3 Cards)

A new card borrows the record of a card that plays the same way (`like`) and lists which cards its effect may pick. The plugin replaces the candidate scan of the new card with a lookup in that list.

`tools/mods/tf3_efeitos.json` (hand written, wins) and `tf3_efeitos_auto.json` (generated by `tf3_efeitos_texto.py` from the card text):

```json
{ "7460": { "like": 5328, "zone": "deck",
            "filter": { "monster": true, "level_max": 4, "name_has": "Gladiator Beast" } } }
```

| zone | effect | donor (`like`) |
|---|---|---|
| `deck` | add 1 card from the Deck to the hand | 5328 Reinforcement of the Army |
| `grave` | add 1 card from the Graveyard to the hand | 5330 The Warrior Returning Alive |
| `grave_summon` | Special Summon from the Graveyard (continuous trap) | 4989 Call of the Haunted |
| `hand` | Special Summon from the hand | 6572 Magnet Circle LV2 |

Filter keys: `monster`, `normal`, `level_min`, `level_max`, `type`, `attribute`, `atk_min`, `atk_max`, `def_min`, `def_max`, `name_has`, `name_is`.
`tools/mods/tf3_efeitos_param.py` turns a filter into the sorted id set stored in `effects.bin`; the plugin side is described in `plugins/src/TF3Cards/README.md`.

## Triggers

The game decides when an effect starts in one predicate (`09f30ddc`), a chain of `id == N` branches. A spec entry with `"trigger_like": <TF1 card id>` makes the game answer that predicate as if the card were the donor
(for example `"trigger_like": 4054` = "when this card is sent from the field to the Graveyard", like Sangan). The effect itself still comes from `like` (the record) and `zone`/`filter`:

```json
{ "7892": { "like": 4054, "trigger_like": 4054, "zone": "deck",
            "filter": { "monster": true, "type": "plant", "def_max": 1000 } } }
```

Checked in a duel: Botanical Girl destroyed by Dark Hole opens the Deck list with only Plant monsters of 1000 or less DEF and adds the chosen card to the hand.

## Known limits

* The first two new ids (6958, 6959) cannot be Normal Summoned as monsters (the card menu only offers "Show Details"); keep Spell/Trap cards there (`tools/mods/tf3_gids.txt` does).
* While a trigger runs, the game shows the donor's name and text in the selection panel.

## Adding a new kind of effect

1. Find a TF1 card that plays the same way and read its record (`tools/game/tf3_efeitos.py`, `mapa_cartas.py`).
2. Find what the card-specific part is: a scan function (table `09f76818`), a chain of ids, or something else. Hook point lists are in `docs/HOOKS.md`.
3. Replace only that part for the new ids and keep the donor's record for everything else.
4. Test in a duel with `tools/test/tf.py` (`TF3_FORCE_CARDS` forces TF3 card ids into the opening hand).
